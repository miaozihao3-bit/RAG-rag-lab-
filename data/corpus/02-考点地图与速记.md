# 02 · 考点地图与速记

> 考试的问法永远是同一个：**这一层的核心矛盾是什么，常用解法有哪几个，代价在哪。**
> 背的时候按"矛盾 → 解法 → 代价 → 指标"四件事背，不要背名词列表。

## 1. 九层一览

| 层 | 分工 | 估算权重 | 一句话抓手 | 样卷对应 |
|---|---|---:|---|---|
| ① | 算力 · 芯片 · AI Infra | 10 | 显存不是够不够，是怎么分 | 判断 3 |
| ② | 算子 · 框架 | 8 | 框架没有优劣，只有适配 | 单选 6 |
| ③ | 训练 · 微调 · 对齐 | 13 | 能用提示词/RAG 解决，先别微调 | 多选 2、判断 5 |
| ④ | 推理 · Serving 优化 | **25** | 所有优化都是拿一点精度/复杂度换大量吞吐 | 单选 7、实践题 |
| ⑤ | RAG · 知识库 | **25** | 切分错了，后面每一步都在放大错误 | 单选 5/13、多选 1 |
| ⑥ | Agent · 工具调用 | **20** | 没有终止条件的 Agent 就是死循环 | 单选 3、判断 1、综合 3 |
| ⑦ | 模型 · 多模态 · 感知 | 16 | 别背模型名，背它在哪一步做了什么 | 单选 1/4/10/15 |
| ⑧ | 评测 · 安全 · 治理 | **20** | 前七层追求更强，这一层回答能不能上线 | 多选 7/8、基础 5(4) |
| ⑨ | 行业应用 · 工程落地 | 16 | 换行业不换骨架：API · 成本 · 审计 · 兜底 | 单选 14、多选 9/10 |

> 权重是四套样卷的估算，用来定投入比例，不是精确分值。**④⑤⑥ 必须能手写链路；①③⑦ 客观题别丢；⑧⑨ 背套路就有分。**

## 2. ① 算力 · 芯片 · AI Infra

**核心矛盾**：算力总量有限，显存是硬天花板；算力不等于性能。

**必背**

- 智能计算系统 = **硬件（芯片 / 存储 / 互联）+ 软件（框架 / 调度 / 算法库）**。
- AI 三要素 = **数据 / 算法 / 算力**（不是应用）。
- CPU：通用、延迟低、核少；GPU：众核、吞吐高、适合矩阵并行。
- 显存约束：模型权重 + KV Cache + 激活；**KV Cache 随并发数和序列长度线性增长**。
- 瓶颈不只看 FLOPS：带宽、互联、调度、数据搬运往往才是瓶颈。
- 芯片生态：NVIDIA + CUDA；昇腾 + CANN；沐曦、天数等。
- 并行方式：数据并行 / 模型并行 / 流水并行 / 张量并行；异构计算 = CPU + GPU/NPU 协同。

**陷阱**： "智能计算系统不包括硬件"（错）；"有卡就一定快"（错）。

---

## 3. ② 算子 · 框架

**核心矛盾**：算子与硬件绑定，框架决定调度效率；选型先看卡，再看模型。

**必背**

- 算子 = 最小计算单元（矩阵乘、卷积、归一化、激活）；CUDA / CANN 是算子层生态。
- 训练框架：**PyTorch 主流**，MindSpore 等国产；推理框架另算。
- **vLLM = Continuous Batching + PagedAttention**（看到组合直接选）。
- TensorRT-LLM：NVIDIA 上编译优化，性能极致，绑定硬件、构建成本高。
- SGLang：RadixAttention、结构化生成、复杂编排、前缀复用。
- TGI：HF 生产级，稳定、集成好。
- ONNX Runtime / TensorFlow Serving：通用部署，不是大模型高吞吐的首选。
- PyTorch 训练循环：`zero_grad → forward → loss → backward → step`。

**陷阱**： "某个框架全面优于另一个"（错，只有适配）；"vLLM 靠 TensorRT"（错）。

## 4. ③ 训练 · 微调 · 对齐

**核心矛盾**：预训练定上限，SFT 定行为，RLHF 定偏好；工程上更常用 PEFT。

**必背**

- 三阶段：**预训练 → SFT → RLHF/对齐**。
- **Chinchilla**：给定算力预算，**参数与数据应同比增加**，不是只堆参数。
- PEFT 家族：**LoRA / Prefix Tuning / P-Tuning v2**；**Full Fine-tuning 不属于 PEFT**。
- LoRA：冻结原权重，训练低秩适配矩阵；QLoRA = 量化 + LoRA。
- RLHF 三件套：**SFT → 奖励模型（RM）→ PPO**；RM 把人类偏好排序变成标量分数；KL 惩罚防止偏离。
- DPO：直接用偏好数据优化，省掉 RM/PPO；RLAIF：AI 反馈。
- 前向：输入到输出逐层计算；反向：链式法则求梯度。
- 超参：学习率、batch size、epoch、warmup；过拟合靠正则、dropout、早停、数据增强。
- 数据：采集 → 清洗/去重 → 标注 → 平衡 → 切分训练/验证/测试。

**顺序原则**：**提示词 → RAG → 微调**。能用前两者解决，先别微调。

## 5. ④ 推理 · Serving 优化（最高权重）

**核心矛盾**：训练一次、推理千万次；同样的卡，怎么服务更多人、更快、更便宜。

**三个问题**：显存怎么省、请求怎么排、token 怎么快。

### 静态 vs 连续批处理

| 维度 | 静态批处理 | 连续批处理 |
|---|---|---|
| 组批 | 等齐一批，整批一起跑 | token 级调度，请求随时进出 |
| 显存 | 按最长请求预留，短请求浪费 | 按实际占用，动态回收 |
| KV Cache | 每序列按最大长度预留 | 分页/按需分配，碎片少 |
| 后果 | 吞吐低、排队久、尾延迟高 | 吞吐高、TTFT/尾延迟更稳 |

### PagedAttention

- 把 KV Cache 切成固定大小 **block**，非连续存储，用 **block table** 映射。
- 好处：消除显存碎片、支持动态增删请求、支持前缀共享、提高并发 batch。
- 这是连续批处理能撑住高并发的前提。

### 投机解码

- 小模型（draft）先自回归生成 K 个候选 token，大模型一次前向并行校验；接受前缀，拒绝则从拒绝点重来。
- 快的原因：大模型一次前向验证多个 token，减少大模型前向次数 → **TPOT 降**。
- 适用：文本可预测（摘要、代码、模板、结构化输出）。
- 变慢：高温/高随机、draft 与大模型分布差太远、短输出、batch 很小、额外 draft 开销大于收益。

### 必会指标

| 指标 | 含义 | 管什么 |
|---|---|---|
| **TTFT** | 首 token 延迟 | 第一口气多快 |
| **TPOT** | 每 token 延迟 | 每口气多快 |
| 吞吐 | tokens/s 或 requests/s | 同时能服务多少人 |
| P99 | 尾延迟 | 稳定性 / SLA |
| 显存利用率 | KV Cache / 权重占用 | 还能不能加并发 |
| 缓存命中率 | 语义缓存效果 | 成本与延迟 |

### 其他手段

量化（INT8/FP8/AWQ/GPTQ）、语义缓存、模型路由、流式输出、前缀缓存、PD 分离、KV Cache 量化。

### 调度

- FCFS：简单，长请求队头阻塞。
- 优先级：保 SLA，但低优先级可能饿死。
- 抢占式：暂停/驱逐低优先级，KV 换出/重算有开销。

**陷阱**：流式输出"减少参数量"（错）；投机解码"永远更快"（错）；连续批处理"只提吞吐不提延迟"（不准确）。

## 6. ⑤ RAG · 知识库（主观题主战场）

**核心矛盾**：让模型回答没学过的东西；核心不在生成，在**检索得准不准**。

**链路（背到能默写）**

```
文档解析 → 切分 → Embedding → 建索引 → 召回 → 重排 → 拼 Prompt → 生成 → 引用/兜底
```

**必背**

- 切分：按章节 / 条款 / 表格切；留 **overlap** 保上下文；整篇一个 chunk 会"问答错位"；chunk 太大稀释，太小断语义。
- 向量化：按领域与语种选 Embedding；余弦相似度，向量先归一化。
- **混合检索**：向量管语义，关键词管实体；股票代码、专有名词、型号靠向量一定失效。
- 重排：粗排 100 → 精排 Top5/Top10；输入候选片段，输出重排顺序；cross-encoder 更准但更慢。
- 多跳检索：答案分散在多个文档，需要连续查几次。
- 评测：**召回率 / 忠实度 / 响应时间**；模型参数量不是 RAG 指标。
- 失败模式：解析错（OCR/表格）、切分错、召回漏、上下文污染、数据过期、越权片段。

**陷阱**：RAG = 微调（错）；只做向量检索（错，实体要关键词）；重排是"再检索一遍"（错）。

## 7. ⑥ Agent · 工具调用

**核心矛盾**：把语言能力接到执行能力；难点不在调用，在**什么时候停**。

**必背**

- 三形态：**聊天机器人（被动应答）→ 工作流（固定步骤）→ 智能体（目标驱动、自主规划）**。
- 2026 政策定义：具备自主**感知、记忆、决策、交互、执行**能力的智能系统。
- Function Calling：用 **Schema** 描述工具名、说明、入参、返回；模型决定调哪个、传什么。
- ReAct：**Reason（想）→ Act（做）→ Observe（看结果）**，再进入下一轮。
- 终止四闸门：**最大轮次 / 超时 / 目标达成判定 / 重复调用检测**。
- 多 Agent 不是银弹：数量增加 ≠ 更可靠、更便宜，反而放大延迟与调试成本。
- MCP：把外部系统接成工具的标准协议；Skills：把流程封装成可复用技能。
- Harness：系统提示词、工具集、上下文管理、循环控制、权限安全。

**陷阱**：Agent = 聊天机器人（错）；Agent 数量越多越好（错）；没有终止条件也能跑（错）。

---

## 8. ⑦ 模型 · 多模态 · 感知

**核心矛盾**：图像 / 语音 / 文本三种信号，各自怎么变成可计算的表示。

### 视觉

- CNN 三层分工：**卷积提特征 → 池化降空间维度 → 全连接分类**；非线性靠**激活函数**，不靠池化。
- 经典模型：LeNet、ResNet（残差解决深层退化）。
- 任务：分类、分割、**目标检测与识别**、OCR、生物特征、行为分析、3D、生成/风格迁移。
- OCR vs VLM：**要"读准数字/字段"用 OCR；要"理解语义/趋势"才用 VLM**。

### 语言

- 基础：分词、词性标注、NER；句法（成分/依存）。
- **Word2Vec**：稠密向量，可做"国王−男人+女人≈女王"类比；但**静态**，一词一向量，不看上下文。
- RNN：能处理变长序列，但长程依赖会**梯度消失** → LSTM/GRU → Transformer。
- Transformer 编码器：**多头自注意力 + 前馈网络 + 残差 + 层归一化**；**掩码注意力属解码器**。
- 上下文词向量（BERT 等）：一词多向量，随上下文变。

### 语音

- 常用声学特征：**MFCC（梅尔频率倒谱系数）**；还有基音、共振峰、响度、掩蔽效应。
- 预处理：预加重、分帧、加窗；时域/频域特征。
- 模型：DNN-HMM、Attention、Transformer；任务：ASR、说话人识别、关键词、语音认证、增强、TTS。

**陷阱**：池化"引入非线性"（错）；Word2Vec"随上下文变化"（错）；编码器"需要掩码注意力"（错）。

## 9. ⑧ 评测 · 安全 · 治理

**核心矛盾**：把"答得对不对"变成可衡量、可追责、可兜底；它不产生新能力，但决定能不能上线。

### 治理四道闸门

| 闸门 | 做什么 | 常见错误说法 |
|---|---|---|
| 入口 | 分类分级、脱敏、加密存储 | "只加密就够了" |
| 链路 | 逐层权限隔离（关键词/向量/图/重排） | "召回后再过滤就行" |
| 出口 | 水印、审计、留痕 | "审计可以延后" |
| 兜底 | 置信度低于阈值转人工 | "提示词写一句禁止泄露就够了" |

### 必背

- 负责任 AI 四项：**分群公平性评估 / 隐私影响评估 / 模型与数据版本追踪 / 风险事件处置与复核**。
- 可信 AI：**可解释性、安全性、公正性、隐私性**。
- 人在回路：用**置信度阈值**把不确定答案拦下来交给人；低风险场景才允许全自动。
- 权限要"逐层"：不是拦一次；重排序阶段还要防越权片段污染答案。
- 成本与审计：API 按 token 精确计量、日志可导出；网页对话做不到。
- 评测看可衡量：召回率 / 忠实度 / 响应时间；参数量不是指标。

**答题句式**：现象（哪个环节泄露/越权）→ 原因（只做了一层/没分级/没留痕）→ 方案（入口-链路-出口-兜底）→ 指标（越权拦截率、审计覆盖率、转人工率）。

## 10. ⑨ 行业应用 · 工程落地

**核心矛盾**：把技术安进业务；考的不是行业知识，是四个共同套路。

| 行业 | 落点 | 技术重点 |
|---|---|---|
| 金融 | 强监管 → 权限隔离 + 全链路审计 | 合规、审计、低延迟 |
| 医疗 | 长尾病种 → 数据增强 + 人在回路 | 罕见病、置信度、转诊 |
| 教育 | 效果可量化 → 完课率等指标 | 自适应路径、答疑 |
| 能源 | 长周期时序 → 预测稳定性优先 | 功率预报、稳定性 |
| 钢铁/制造 | 视觉 + 优化决策 → 准确率与可解释 | 高炉火焰、排产 |
| 电商/零售 | 规模化 → 走 API，不走网页对话 | 批量文案、客服 |

**四个共同套路（写大题时逐条对照）**

1. 用 **API**，不用网页对话。
2. 成本可核算（按 token 计量）。
3. 审计可追溯（日志留痕）。
4. 人的兜底（低置信度转人工）。

**通用答法**：先判断"它属于哪个分工的技术"，再套四个套路，最后补一个可量化指标。

## 13. 九层一句话默写（考前 5 分钟）

1. 算力：显存是天花板，算力不等于性能。
2. 算子框架：没有优劣，只有适配；vLLM = 连续批处理 + 分页 KV。
3. 训练微调：预训练定上限、SFT 定行为、RLHF 定偏好；先提示词/RAG，再微调。
4. 推理 Serving：省显存、排请求、快 token；TTFT/TPOT/吞吐/P99。
5. RAG：切分、召回、重排决定天花板；混合检索 + 重排 + 评测。
6. Agent：目标驱动、工具调用、四道终止闸门。
7. 模型多模态：卷积提特征、池化降维、全连接分类；Word2Vec 静态；Transformer 编码器无掩码。
8. 治理：入口分级脱敏、链路逐层权限、出口水印审计、兜底人在回路。
9. 行业：API、成本、审计、兜底；再补一个可量化指标。
