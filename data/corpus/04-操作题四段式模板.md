## 1. 先看分值，决定写几点

| 分值 | 至少写 | 结构 |

> 答题纸不是作文。**分点、短句、术语、指标**，比长段落更容易拿分。

## 2. 四段式（任何大题都能套）

| 段 | 写什么 | 句式 |
|---|---|---|
| ① 现象 | 一句话复述业务 + 一句话点矛盾 | "当前……导致……，核心矛盾是……" |
| ② 原因 | 点名技术机制，不怪"模型不行" | "根因在……机制：……" |
| ③ 方案 | 分点，每点"动作 + 机制" | "① 在入口……；② 在链路……；③ 在出口……" |
| ④ 指标 | 怎么知道做对了 | "以……率达到……、P99……、越权拦截率……衡量" |

### 示例：票据数字识别

- 现象：直接让 VLM 读票据金额，数字会错，且无法溯源。
- 原因：视觉编码器对细粒度数字不敏感；缺少原文坐标锚点。
- 方案：票据/表格走 OCR 取结构化字段，回写原文坐标；趋势图才用 VLM；答案附引用块。
- 指标：数值字段准确率 ≥ 99%；每条结论可溯源；低置信度转人工率。

> 差别只有两件事：有没有**分流规则**，有没有**可验证的落点**。

### 4.2 Linux 日志清理（5 分）

先诊断，再清理，最后复核：

```bash
df -h
du -sh /var/log/* | sort -h
truncate -s 0 /var/log/app.log
journalctl --vacuum-size=500M
logrotate -f /etc/logrotate.conf
find /var/log -name "*.gz" -mtime +30 -delete
df -h
```

注意：不要 `rm` 正在写入的日志（句柄未释放，空间不回收）；用 `truncate` / logrotate；保留审计与安全日志；确认服务用户权限；清理后复核磁盘。

## 5. 实践题 Q1：金融智投（35 分里的 15 分）

> 题干里每个"同事发言"都是送分点：**先判错，再给正解**。每小问 5 分，写 4–5 点。

### （1）Serving 优化（5 分）

**结论**：不做单点优化，做分层 Serving：缓存 → 路由 → 组批 → 解码，四层各自省一段成本。

1. **语义缓存**：query 向量化，相似度阈值命中；缓存 key 带**费率版本/知识库版本 + TTL**；版本变更即失效，避免旧费率。
2. **模型路由**：按意图/长度/风险分流；简单咨询走小模型，复杂投研走大模型；高风险强制大模型 + 人工复核。
3. **连续批处理**：token 级调度，请求随时进出；提高 GPU 利用率，降低排队。
4. **投机解码**：小模型起草 + 大模型校验；适合模板化/可预测文本，随机性强的场景关闭。
5. **指标**：缓存命中率、TTFT P99、TPOT P99、吞吐 tokens/s、GPU 利用率、单请求成本、SLA 违约率。

**甄别**：小李"全程大模型不优化"错；王工"只扩容"错；小陈"缓存坚决不用"错（可版本化）；老张"连续批处理没必要"错。

### （2）权限与租户隔离（5 分）

**结论**：权限不是"事后过滤"，是**从入库到重排的逐层约束**。

1. **租户隔离**：按部门/客户建独立 collection 或 namespace；文档带 `tenant_id / dept_id / ACL / 密级`。
2. **关键词召回**：查询时带 ACL filter，只检索可见范围。
3. **向量召回**：在向量库查询条件中带 `tenant_id` / `acl_group`，不做全库 top-k 再过滤。
4. **图召回**：节点/边同样校验权限；低频也要校验。
5. **重排**：对候选片段再次校验 ACL，防越权片段混入；生成前裁剪。
6. **审计**：记录谁、何时、查了什么、返回了什么。

**甄别**：统一库错；提示词约束错；召回后过滤错；图检索不校验错。

### （3）合规三件套（5 分）

**结论**：入口脱敏、出口水印、全程审计，三层缺一不可。

1. **入库**：分类分级（员工隐私/客户/投研/合同/风控）→ 脱敏/掩码 → 加密存储 + KMS → 最小化 + 保留期限。
2. **查询**：查询水印（用户 ID/请求 ID），输出可追踪；防多段拼接还原。
3. **全链路审计**：认证授权、访问日志、异常告警、人工复核、回滚。
4. **人在回路**：高风险/低置信度转人工，阈值 + 留痕。
5. **指标**：敏感字段脱敏覆盖率、越权拦截率、审计覆盖率、泄露事件数。

**甄别**：只加密错；提示词"禁止泄露"错；不脱敏错；审计延后错。

## 6. 实践题 Q2：推理工程（20 分，4 小问 ×5）

### （1）静态 vs 连续批处理（5 分）

1. **组批逻辑**：静态等一批凑齐/固定 batch，整批一起跑；连续按 token 调度，请求随时进出。
2. **显存占用**：静态按最长请求预留，短请求浪费；连续按实际占用动态回收。
3. **KV Cache**：静态每序列按最大长度预留；连续分页/按需分配，碎片少。
4. **PagedAttention**：KV Cache 切 block，非连续存储 + block table；消碎片、支持动态增删与共享，才撑得住连续批处理。
5. **指标**：吞吐、TTFT、TPOT、P99、显存利用率。

### （2）投机解码（5 分）

1. **原理**：小模型 draft 自回归生成 K 个候选；大模型一次前向并行校验；接受前缀，拒绝则从拒绝点重来。
2. **为什么快**：大模型一次前向验证多个 token，减少大模型前向次数 → TPOT 降。
3. **适用**：摘要、代码、模板、结构化输出等可预测文本；draft 与大模型分布接近。
4. **边界/代价**：高温高随机、短输出、batch 小、draft 质量差时，额外开销可能大于收益，反而变慢。
5. **指标**：接受率、TPOT、吞吐、额外显存。

### （3）框架选型（5 分）

1. **选型维度**：延迟/吞吐、模型与硬件适配、量化、分布式、API 兼容、可观测性、稳定性、许可证、成本、团队熟悉度。
2. **vLLM**：PagedAttention + 连续批处理；吞吐高、易用、模型覆盖广。
3. **TGI**：HF 生产级；稳定、集成好；高级调度少一些。
4. **SGLang**：RadixAttention、结构化生成、复杂编排、前缀复用。
5. **TensorRT-LLM**：NVIDIA 编译优化，极致性能；绑定硬件、构建成本高、灵活性低。

### （4）调度（5 分）

1. **FCFS**：简单；长请求队头阻塞，短请求被拖。
2. **优先级**：保 SLA；低优先级可能饿死。
3. **抢占式**：暂停/驱逐低优先级；KV 换出/重算有开销，复杂度高。
4. **组合策略**：按 SLA 分级 + 长请求单独队列 + 限额/限流 + 弹性扩容。
5. **监控指标**：QPS、排队长度、TTFT/TPOT P99、GPU 利用率、KV Cache 使用率、batch size、拒绝率、SLA 违约率。
