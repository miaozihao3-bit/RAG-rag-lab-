# 06 · Harness 与企业落地（第三、四讲）

> 这两讲不直接出客观题原题，但**综合题 3 的话术、治理题、行业题**都从这里来。
> 记住框架，不要背数字；数字只记 8 个，其余知道"有出处"即可。

## 1. Harness 是什么

> Harness 原指套在马身上的挽具，这里指**包裹在大模型外围的工程框架**：定义指令、装配工具、管理上下文、控制循环、约束权限，把"会聊天"的模型变成"会干活"的智能体。

### 五个组成部分

| 组件 | 管什么 |
|---|---|
| 系统提示词 | 身份、目标、边界 |
| 工具集 | 文件、终端、网络、检索、业务 API |
| 上下文管理 | 裁剪、压缩、装配 |
| 循环控制 | 何时行动、何时停止 |
| 权限与安全 | 审批、沙箱、白名单 |

### 模型 vs Harness

| 维度 | LLM（模型） | Harness（框架） |
|---|---|---|
| 本质 | 理解、推理、生成 | 编排与约束的工程系统 |
| 形态 | 权重 / API | 提示词、工具代码、配置、循环逻辑 |
| 迭代 | 以月计 | 以天计 |
| 决定 | 能力上限 | 行为方式 |
| 可替换 | 换模型 ≈ 换引擎 | 多数可换模型底座 |
| 典型失败 | 幻觉、知识过期 | 死循环、上下文爆炸、权限失控 |

**排查口诀**：答非所问先看模型，原地打转先看 Harness。
**一句话**：模型决定能力上限，Harness 决定行为方式。

## 2. Agent 循环

```
用户指令
  → 组装上下文（系统提示 + 记忆 + 历史 + 工具结果）
  → LLM
  → stop_reason?
       tool_use → 执行工具 → 结果写回上下文 → 下一轮
       end_turn → 输出结果，本轮结束
```

- 模型只回两个信号：**tool_use（我要用工具）**、**end_turn（我说完了）**。
- 循环由 `stop_reason` 驱动；Harness 负责组装、执行、校验，并用**步数/超时**兜底。
- 这正好对应综合题 3 的终止条件：最大轮次 + 超时 + 目标达成 + 重复调用检测。

### 循环之外的四个机制

| 机制 | 管什么 | 失控后果 |
|---|---|---|
| Context | 裁剪工具输出、压缩历史 | 窗口被日志灌爆，费用飙升 |
| Permission | 命令分级、沙箱、密钥隔离 | 误删、密钥泄漏 |
| Memory | `CLAUDE.md` / `AGENTS.md` 带项目规范 | 每次重复交代，反复踩坑 |
| Skills | 常用流程封装；MCP 接外部系统 | 经验无法沉淀 |

### 选型四问

1. 工作发生在终端还是编辑器？→ CLI / IDE。
2. 代码与数据能否出域？→ 开源自部署 / 闭源 SaaS。
3. 绑定一家模型还是随时换底座？→ 官方 Harness / 模型无关。
4. 预算与规模？→ 免费额度 / API 按量 + 配额治理。

**落地建议**：圈定 2–3 款，用同一批真实任务试跑两周，对比"评审时间 / 一次通过率 / 成本"。

## 4. 企业 Agent 是什么

> 智能体（Agent）：具备自主**感知、记忆、决策、交互与执行**能力的智能系统。
> ——《智能体规范应用与创新发展实施意见》（2026-05）

**聊天机器人交付"回答"，Agent 交付"办成的事"。**

从模型能力到任务执行，从单点应用到智能协同。

## 7. 一单活怎么干完：五步链路

```
读材料 → 拆任务 → 调工具 → 做分流 → 留全程
```

以平安理赔为例：

1. **读材料**：文档解析读病历、发票、明细；信息采集自动化率 >70%。
2. **拆任务**：按 1000+ 理赔要点拆成核验/责任/理算/复核。
3. **调工具**：条款库、医学知识库、核心业务系统。
4. **做分流**：齐全明确 → 自动结案；存疑 → 交互卡片转人工。
5. **留全程**：每一步可审计、可追溯。

> 任何行业的 Agent，拆开都是这个骨架。综合题 3 的"就医陪诊"就是：读需求 → 拆任务 → 调 3 个自建 API + 3 个平台 API → 有号/无号分流 → 输出计划 + 调用记录。

## 8. 人在哪个环节

| 能力层 | 风险 | 人的位置 |
|---|---|---|
| 文件层 | 低 | AI 可自动 |
| 知识层 | 中 | AI 起草，人审 |
| 系统层 | 较高 | AI 执行，人授权 |
| **决策层** | **高** | **必须保留人工审批** |

- 工业报告：**"认知可概率化，执行必须受约束"**。
- Adecco：事先告知"你在与 AI 交谈"，最终判断由招聘官做。
- 主流形态：**AI 干量，人把关**。

## 9. 企业怎么把 Agent "装"进去

### 落地五步法

```
场景筛选 → 试点 → 评估 → 沉淀 → 复制
```

### 生产级"七件套"（缺一件，试点永远是试点）

**数据 · 身份 · 权限 · 审批 · 审计 · 回滚 · 人工兜底**

### 分水岭

- 高绩效企业约 **3/4** 重新设计工作流；其他企业约 **1/4**。
- 失败典型：把 Agent 硬塞进旧流程，指望它自己适应。
- 结论：**瓶颈不在模型，而在数据、权限、治理、组织协同。**

## 12. 能力阶梯与趋势

| 级别 | 能力 | 企业付费点 |
|---|---|---|
| L1 围观者 | 知道 AI，偶尔问 | |
| L2 使用者 | 日常写文案、查资料 | |
| L3 熟练工 | 稳定工作流、复用模板 | **付费区** |
| L4 编排者 | 拆任务链、定验收标准 | **付费区** |
| L5 架构者 | 嵌进组织流程、沉淀资产、定治理 | |

- 评价轴变了：从"你懂不懂 AI"，到"你能不能让 AI 把一件真实的事做完，并为结果负责"。
- 三个趋势：
  1. **使用者之变**：模型为模型生产（决策模型）；软件为模型而建（MCP）；服务为 Agent 优化（GEO→AEO）。
  2. **范式换代**：第一代"提示词 + MCP + 工作流"→ 第二代"Harness + MCP + Skill"。
  3. **FDE 出现**：前线部署工程师 = 业务判断（Echo）+ 技术落地（Delta）；Skill 要像软件一样维护。

**金句**（大题可引用）："Agent = Model + Harness——模型决定上限，工程决定下限。"

## 13. 怎么用在考卷上

### 问 Agent 定义 / 形态

> Agent 是具备自主感知、记忆、决策、交互与执行能力的智能系统；与聊天机器人不同，它交付的是"办成的事"，形态从聊天机器人 → 工作流 → 目标驱动的智能体演进。

### 问终止 / 可靠性

> 用最大轮次、超时、目标达成判定、重复调用检测四道闸门；多 Agent 不是银弹，数量增加会放大延迟与调试成本。

### 问企业落地

> 五步法：场景筛选 → 试点 → 评估 → 沉淀 → 复制；生产级七件套：数据、身份、权限、审批、审计、回滚、人工兜底；瓶颈不在模型，在数据、权限、治理与组织协同。

### 问治理

> 入口分级脱敏、链路逐层权限、出口水印审计、兜底人在回路；权限三边界：用户独占决策、需用户授权、Agent 自主；高风险决策保留人工审批。

### 问综合题 3 的设计

> System Prompt 约束"不虚构科室/号源/距离/天气、分诊不替代诊断"；工具 Schema 描述 3 个自建 API + 天气/地图/搜索；循环加四道终止闸门；输出固定结构 + 调用记录；Mock 必须含"已满/停诊"异常分支。
