## 4. 必须回看的 10 道题

### ① 单选 2：长上下文"中部塌陷"

- 现象：关键信息在开头/结尾准，在中部不准。
- 原因：注意力机制对长文中部的有效关注弱，位置偏置 + 注意力稀释。
- 方案：关键信息前置/分段摘要/滑动窗口检索/重排；不是"截断"。
- 指标：不同位置的召回率、答案准确率。

### ② 单选 6：vLLM 的两个标志

| 框架 | 标志性技术 | 定位 |
|---|---|---|
| **vLLM** | Continuous Batching + PagedAttention | 高吞吐、易用、模型覆盖广 |
| TGI | HF 生产级服务 | 稳定、集成好，调度特性少一些 |
| SGLang | RadixAttention + 结构化生成 | 复杂编排、前缀复用 |
| TensorRT-LLM | 编译优化 | NVIDIA 上极致性能，绑定硬件、构建成本高 |

### ③ 单选 7：流式输出改的是"怎么吐"

- 降低 **TTFT**（首 token 延迟），实现逐 token 响应。
- 不减少参数量、不增加训练吞吐、不提高精度。
- 常与 SSE / WebSocket 一起考。

### ④ 单选 9：专家系统 vs 机器学习

- 专家系统：人工把规则编码进去；规则一多会冲突、难维护。
- 机器学习：从历史数据学特征，减少人工编码成本，但需要数据、可解释性弱。
- 不是"直接读取专家思维"，也不是"完全不需要人工"。

### ⑤ 单选 10：Word2Vec 的能与不能

- 能：稠密向量、语义/语法类比运算（国王−男人+女人≈女王）。
- 不能：静态词向量，一词一向量，不随上下文变化；多义词歧义不能彻底消除。
- 对比：BERT/Transformer 上下文相关。

### ⑥ 多选 5：编码器 vs 解码器

| 模块 | 组成 | 掩码注意力 |
|---|---|---|
| **编码器** | 多头自注意力 + 前馈网络 + 残差 + 层归一化 | 不需要 |
| 解码器 | 掩码自注意力 + 交叉注意力 + 前馈 + 残差 + 层归一化 | 需要（防止看到未来） |

### ⑦ 多选 8：模型能力边界的四句话

- 常见病好：高频数据上的文本组织能力强。
- 罕见病差：难以创造训练分布外的新知识，是固有局限。
- 同问两答都自信：输出不确定 + 校准不足。
- "完全不可用、无法缓解"：绝对化，错；可以用 RAG、人在回路、置信度阈值缓解。

### ⑧ 多选 9 / 10：API vs 网页对话

| 维度 | API | 网页对话 |
|---|---|---|
| 批量 / 编程 | 支持脚本批量 | 不适合 |
| 风格固化 | system prompt | 难统一 |
| 成本计量 | 按 token 精确 | 无细账 |
| 审计 | 日志可导出（时间/内容/响应） | 历史难自动导出 |
| 结论 | **批量、合规、可核算场景一律 API** | 只适合人工临时问答 |

### ⑨ 判断 10：涌现能力可能是"度量幻觉"

- 原说法：BIG-Bench 90% 任务涌现，换连续度量仍跃升，所以与度量无关。
- 事实：换成连续/平滑度量后，很多"突然跃升"消失；说明涌现对度量选择敏感。
- 考点：**"涌现"不是无条件事实，先问度量口径**。

### ⑩ 判断 13：401 / 400 / 429

| 状态码 | 含义 | 记忆 |
|---|---|---|
| 400 | 请求参数格式错误 | 你写错了 |
| 401 | 未认证 / 密钥无效 | 没带对钥匙 |
| 403 | 已认证但无权限 | 钥匙不对门 |
| 429 | 触发限流 | 太快了，重试/退避 |
| 5xx | 服务端错误 | 对面坏了，可重试 |

### 5.2 Linux 日志清理（5 分）

```bash
# 1. 先看谁大
df -h
du -sh /var/log/* | sort -h

# 2. 清空正在写入的日志（不要直接 rm）
truncate -s 0 /var/log/app.log

# 3. 按 journal 保留上限清理
journalctl --vacuum-size=500M
journalctl --vacuum-time=7d

# 4. 触发 logrotate
logrotate -f /etc/logrotate.conf

# 5. 删旧归档（确认后再执行）
find /var/log -name "*.gz" -mtime +30 -delete
```

注意：不要 `rm` 正在被进程打开的文件（文件句柄还在，空间不释放）；用 `truncate` 或 logrotate；保留审计/安全日志；确认服务用户权限；清理后 `df -h` 复核。

### 5.3 RLHF 与奖励模型（5 分）

- 论文：`Training Language Models to Follow Instructions with Human Feedback`（InstructGPT）。考场上原文在 `C:\素材`。
- 三件套：**SFT → 训练奖励模型（RM）→ PPO 优化策略**。
- 奖励模型作用：把人类的**偏好排序**（A 比 B 好）学成一个**标量分数**，让策略可以用奖励信号做优化；同时用 KL 惩罚约束不要偏离 SFT 太远。
- 对齐方向：更多/更高质量的人类反馈、RLAIF（AI 反馈）、DPO 等更稳定的偏好优化、可扩展监督、安全与拒答。

### 5.4 PyTorch 训练循环（5 分）

```python
optimizer.zero_grad()          # ① 梯度清零
loss = F.cross_entropy(outputs, labels)
loss.backward()                # ② 反向传播，求梯度
optimizer.step()               # ③ 参数更新
```

顺序记死：**zero_grad → forward → loss → backward → step**。

### 5.5 河道 AI 巡检（15 分）

1. **[A] 定位漂浮物**：目标检测（如 YOLO / Faster R-CNN），输出边界框 + 类别 + 置信度。
2. **[B] 区分塑料瓶 / 树枝**：颜色（透明/白/绿 vs 褐/灰）、纹理（光滑反光 vs 粗糙）、形状（瓶身规则 vs 枝状不规则）、边缘/长宽比。答两类即可。
3. **补代码**：`files=files`、`data=data`、`headers=headers`。
4. **置信度 <60% 转人工**：**人在回路（human-in-the-loop）**；补一句"阈值 + 转人工 + 留痕"才完整。

## 6. 实践应用题得分点（35 分）

> 完整写法见 [[04-操作题四段式模板]]。这里只列"必须出现"的词。

### 6.1 金融智投：Serving 优化（15 分）

- **语义缓存**：query 向量 + 阈值命中；缓存 key 带**版本号/费率版本/TTL**，避免旧规则；命中直接返回，未命中走链路。
- **模型路由**：简单问题走小模型/规则，复杂投研走大模型；按意图/长度/风险分级。
- **连续批处理**：token 级调度，请求可随时进出，提高 GPU 利用率。
- **投机解码**：小模型起草 + 大模型校验；适合可预测文本，随机性强的场景慎用。
- **指标**：缓存命中率、TTFT P99、TPOT P99、吞吐 tokens/s、GPU 利用率、单请求成本、SLA 违约率。
- **甄别**：小李"全程大模型不优化"错；王工"只扩容"错；小陈"缓存坚决不用"错；老张"连续批处理没必要"错。

### 6.2 金融智投：权限与租户隔离（15 分）

- 租户/部门级 **collection 或 namespace 隔离**；文档带 `tenant_id / dept_id / ACL / 密级` 元数据。
- **关键词、向量、图三路召回都在查询时带权限过滤**，不是召回后过滤。
- **重排序前再次校验**片段 ACL，防止越权片段混入；生成前裁剪。
- 图检索同样校验节点/边权限。
- 审计：谁、何时、查了什么、返回了什么。
- **甄别**：统一库错；提示词约束错；召回后过滤错；图检索不校验错。

### 6.3 金融智投：合规三件套（15 分）

- **入库**：分类分级 → 脱敏/掩码（PII、客户信息、涉密合同）→ 加密存储 + 密钥管理 → 最小化 + 保留期限。
- **查询**：查询水印（用户/请求 ID）、输出审计、防拼接还原。
- **全链路**：认证授权、日志留痕、异常告警、人工复核、回滚。
- **甄别**：只加密错；提示词"禁止泄露"错；不脱敏错；审计延后错。

### 6.4 实践题 2（20 分）：组批 / 投机 / 框架 / 调度

**（1）静态 vs 连续批处理**

| 维度 | 静态批处理 | 连续批处理 |
|---|---|---|
| 组批 | 等一批凑齐/固定 batch，整批一起跑 | token 级调度，请求随时进出 |
| 显存 | 按最长请求预留，短请求浪费 | 按实际占用，动态回收 |
| KV Cache | 每序列按最大长度预留 | 分页/按需分配，碎片少 |
| 结果 | 吞吐低、排队久 | 吞吐高、TTFT/尾延迟更稳 |

**PagedAttention**：KV Cache 切成固定大小 block，非连续存储 + block table 映射；消除碎片、支持动态增删与共享，才能撑住连续批处理的高并发。

**（2）投机解码**

- 原理：小模型（draft）自回归生成 K 个候选 token，大模型一次前向并行校验；接受前缀，拒绝则从拒绝点重来。
- 加速原因：大模型一次前向验证多个 token，减少大模型前向次数 → TPOT 降。
- 边界：文本可预测（摘要、代码、模板）收益高；高温/高随机、draft 与大模型分布差太远、短输出、batch 很小时，额外开销可能反而变慢。

**（3）框架选型**

- 维度：延迟/吞吐、模型与硬件适配、量化、分布式、API 兼容、可观测性、稳定性、许可证、成本、团队熟悉度。
- vLLM：PagedAttention + 连续批处理，吞吐高、易用、模型广。
- TGI：HF 生产级，稳定、集成好。
- SGLang：RadixAttention、结构化输出、复杂编排、前缀复用。
- TensorRT-LLM：NVIDIA 编译优化，极致性能；绑定硬件、构建成本高、灵活性低。

**（4）调度**

- FCFS：简单，长请求队头阻塞，短请求被拖。
- 优先级：保 SLA，但低优先级可能饿死。
- 抢占式：暂停/驱逐低优先级，KV 换出/重算有开销，复杂度高。
- 监控：QPS、排队长度、TTFT/TPOT P99、GPU 利用率、KV Cache 使用率、batch size、拒绝率/错误率、SLA 违约率。

## 7. 综合题评分点（30 分）

### 7.1 代码修复（10 分）

- 密钥：环境变量读取；不打印、不入日志。
- HTTP：统一封装 client；设置 timeout；非 2xx 抛明确异常；响应结构校验。
- 依赖注入：client 可替换，便于测试；`ResearchAgent` 只编排。
- 行为：保留"初稿 → 审校"两次调用。
- 测试：至少 2 个（缺 key / 非 2xx / 结构错误 / 超时）。

### 7.2 程序设计（10 分）

- 定位：`UnicodeDecodeError` 多来自把非 ASCII 文本按 `ascii` 编码/解码。
- 修复：统一 UTF-8；哈希直接对 `bytes` 做；必要时 `unicodedata.normalize`；对外接口不变。
- 测试：正常输入 + emoji 输入；断言不抛异常且结果稳定。

### 7.3 智能体开发（10 分）

- 3 个自建 API：`department_guide`、`hospital_search`、`pharmacy_query`；JSON；Mock 含"已满/停诊"异常。
- 平台 API：天气 / 地图 / 搜索；不得虚构。
- 规划：症状 → 分诊 → ≥2 家号源 → 路线 → 药房 → 天气 → 汇总。
- 决策：有号、近、医保定点优先；首选满/停诊自动改选；按路程倒推出发时间；材料清单来自 API；高温/暴雨提醒。
- 交付 5 样：源码 / API + Mock / System Prompt / 调用记录 / 就医计划。
- 终止：最大轮次 + 超时 + 重复调用检测 + 目标达成。
